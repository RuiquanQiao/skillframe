让 Skill 拥有 UI：调研报告

2026-10-17 · 乔睿泉（Ruiquan Qiao）· 项目：skillframe

结论速览

方向对，但你不是唯一想到的人：Anthropic 已经分两步做了一半，窗口期在收窄。值得做，前提是站在开放标准上、用具体的 UI skill 引流，而不是另起一套协议。

  • 官方已有的两半：2026-01 的 MCP Apps 让任意 HTML UI 进入 Claude 和 ChatGPT 的聊天，但 Claude Code 不渲染。两周前（2026-10-01）的 Claude Code mods 让插件在 Claude Code 里画侧边面板，但只能用固定组件，没有 HTML 和图片。
  • 真实的空位：“任意 HTML 工作台 + 本地 coding agent 并排、双向联动 + 由 skill 自己携带”，目前没有通用开源方案。你的 Resume Studio 正好是这个形态的一个实例。
  • “用户自带订阅”模式可行，前提是只启动用户自己登录的官方 claude / codex CLI，不碰凭证；产品名不能带 Claude。Anthropic 的相关政策今年变过至少三次。
  • 建议：先花 1 周验证“官方 app 已经够用”的两条捷径；不够用，再从 Resume Studio 抽出一个跨 Claude Code / Codex 的桌面宿主，UI 用 MCP Apps 这个开放格式，并用 2–3 个旗舰 UI skill 发布。
  • 成败指标：是否有别人写带 UI 的 skill，而不是 star 数。

概念扫盲：Skill、Plugin、MCP、Mod 分别是什么

一句话：Skill 是给 agent 读的说明书，MCP 是给 agent 用的工具，Plugin 是把它们打成一个包的安装单位，Mod 是 Claude Code 插件里唯一能在界面上画东西的部分。你说的“带 UI 的 skill”，在 Claude Code 体系里最接近“Skill + Mod（+ MCP）打成一个 Plugin”。

名称本质写什么能改什么能画 UI 吗
Skill一个 SKILL.md 文件夹（可带脚本、模板），agent 需要时才读全文Markdownagent 知道什么、怎么做否
MCP server独立进程或远程服务，给 agent 提供工具（tools）和数据任何语言agent 能调用哪些工具在 claude.ai / Claude Desktop 聊天里可以，经由 MCP Apps 扩展
Subagent一个独立上下文的“分身”，用来隔离长任务Markdown 定义任务拆分与上下文隔离否
Settings hook在生命周期事件（如每次改文件后）跑的 shell 命令或 HTTP 请求脚本 + settings.json拦截、放行、记录事件否
Mod在 Claude Code 进程内运行的 JS/TS 事件处理函数JavaScript / TypeScript工具调用、提示词、命令、界面是：侧边面板、提示框上方横幅、状态栏、toast，还能改写 Claude Code 自己画的部分
Plugin一个目录 + .claude-plugin/plugin.json 清单，把上面任意几样打包清单 JSON安装、版本、分发取决于里面有没有 Mod
Marketplace一个列出插件及下载地址的 marketplace.json，通常是一个 GitHub 仓库JSON分发渠道—

三个容易混的点：

  • Skill 本身已是开放标准（agentskills.io）。SKILL.md 格式被 Claude Code、Codex 等多个 agent 读取，所以“文档型 skill”天然跨工具；而 Mod 只在 Claude Code 里跑。
  • Plugin 不是 MCP。Plugin 是打包格式，里面可以带 MCP server，也可以不带。Codex 也有自己的 plugins（2026-03），同样是 skill + MCP 的打包。
  • 装上的插件每轮都占上下文：每个 skill 的名字和描述常驻，全文按需加载；MCP 工具描述也会占 token。这限制了“一个超大全家桶插件”的做法。

已有的同类方案：官方已经做了两半

你想要的“agent app 里有一块显示定制 UI 的区域”，Anthropic 已经分两条线做出来了，但两条线各缺一半。这是本报告最重要的发现。

  • MCP Apps（2026-01-26 上线）：MCP server 可以返回一段完整的 HTML/JS，在 claude.ai、Claude Desktop 聊天、移动端、ChatGPT、VS Code、Goose 里以沙箱 iframe 渲染，支持内联卡片、轮播、全屏和画中画。UI 能回调 server 的工具。但官方文档明确写了：Claude Code 只把工具当文字调用，不渲染 UI。设计规范还要求“别做复杂多步工作流、别做深层导航”。它的定位是“对话里的小应用”，不是“与 agent 长期并排的工作台”。
  • Claude Code mods（2026-10-01 随 v2.1.287 发布）：插件里的 JS/TS 可以在终端、桌面端 Code 标签页、VS Code 里画侧边面板和提示框上方横幅，还能用 $.prompt.submit 替用户发消息、拦截工具调用、读写文件。这几乎就是你说的“带 UI 的 skill”。但面板只能用一套固定组件拼：Box、Text、Button、Input、Select、Markdown、Code、Svg（最多 131,072 字符），没有 HTML/webview，桌面端也不支持 Image。自定义绘制的 Client 按字符格子坐标工作，不是 DOM。

换句话说：“任意 HTML 的富 UI”和“跑在本地、能改文件的 agent”今天在官方产品里还没有放在同一个窗口里。简历实时 PDF 预览、拖拽画布、带浏览器的网申工作台，用 mods 做不出来；用 MCP Apps 可以做出来，但只能在聊天里用，进不了 Claude Code。这就是空位所在，也是风险所在：官方把两条线合并，只是时间问题。

“借用户的订阅”：可以，但只有一种姿势是安全的

安全姿势是：你的程序去启动用户本机上未经修改、由用户自己登录的 claude / codex 可执行文件，而不碰任何登录凭证。career-ops 和你的 Resume Studio 都是这个姿势。

Anthropic 官方《Legal and compliance》页面当前写的是：

  • 允许：最终用户用自己的 Claude 订阅登录未经修改的 Claude Code 二进制，包括嵌在别人的产品里跑。
  • 不允许：第三方在自己的 app 里提供“Claude.ai 登录”；代替用户把请求走 Free / Pro / Max 凭证；收集、存储、中转 Claude.ai 的凭证或会话 token。
  • 用 Agent SDK 做产品的开发者：文档要求用 API key。
  • 命名：不能把 “Claude Code” 或 “Anthropic” 用在自己的产品名、logo 里，只能在文字里如实说“跑在 Claude Code 上”。
  • Anthropic 保留不经通知就执行这些限制的权利。

但整个 2026 年这条政策反复变过，平台风险是真实的：

日期变化
2026-10-07客服中心：Max 和 Team 套餐附带每月 API 额度，可用于 Agent SDK、claude -p；Pro 不在其列。Agent SDK、claude -p 和第三方 app 仍可用订阅额度
2026-06-15原定把 SDK 使用改成单独按 API 价计费的方案当天暂停，“nothing has changed”
2026-05-13宣布解除 4 月的封禁，改为单独的 SDK 额度（据 BetterClaw 整理）
2026-04-04第三方工具（包括 OpenClaw）的 OAuth 访问被切断
2026-02-19条款明确：订阅 OAuth token 只用于 Claude Code 和 Claude.ai（GIGAZINE）

OpenAI 这边更开放：2026 年 9 月的 “Sign in with ChatGPT” 让 Plus / Pro 用户把自己的套餐额度授权给合作工具使用（The New Stack），首批合作方据报包含 OpenCode、OpenClaw 等开源项目。

对你的含义：

  1. 底层永远调用官方 CLI（claude -p --input-format stream-json 或 ACP 适配器），不自己实现 agent 循环，也不碰 token。
  2. 同时支持 Codex，把单一厂商的政策风险分散掉。
  3. 产品名里不要带 Claude。

可行性：空位真实存在，但窗口期可能只有几个月

技术上完全可行，你已经在 Resume Studio 里做出了原型；难点不在技术，而在“别人为什么用”和“官方会不会先做完”。

空位是什么

今天没有一个产品同时满足这四条：

  1. UI 是任意 HTML（能显示 PDF、画布、复杂表单）；
  2. 与本地 coding agent 的会话长期并排，而不是聊天里一张一次性卡片；
  3. UI 和 agent 双向联动：UI 能发消息给 agent，agent 改了文件 UI 自动刷新；
  4. 由 skill 自己声明和分发，用户装一个 skill 就得到一个工作台。

mods 缺第 1 条，MCP Apps 缺第 2 条，GUI 外壳缺第 4 条，OpenClaw Canvas 绑定自家生态且仅 macOS。

别人为什么会用

  • skill 作者：不用像你一样自己重写一遍聊天框、权限卡片、AskUserQuestion、中断、上传文件。你在 Resume Studio 里踩过的坑（“尽可能移植但总有疏漏”）就是卖点。
  • 终端用户：不会因为“基础设施”而来，只会因为某个具体的好用 skill 而来。career-ops（75.3k star）和 OpenClaw（392k star）红的都是具体价值，不是架构。
  • 结论：基础设施很少靠自己走红。先用一两个杀手级 UI skill 引流，框架作为“你也能这样做”的第二层。

风险

风险为什么应对
官方补齐mods 两周前刚发布，已经有 Svg 和 Client；给面板加 HTML，或让 Code 标签页渲染 MCP Apps，都是顺理成章的下一步UI 直接用 MCP Apps 这个开放格式写；官方补齐时，你生态里的 skill 自动在官方宿主里也能跑，你的价值转向跨 agent 和开发工具
订阅政策Anthropic 2026 年内改了至少三次只调用官方 CLI，同时支持 Codex
冷启动没有 skill 就没有用户，没有用户就没有作者自己先产出 2–3 个旗舰 UI skill；把现有热门 skill（如 career-ops）做成 UI 适配示例
安全带 UI 的 skill 就是在用户机器上跑的第三方代码UI 放沙箱 iframe，文件读写走显式权限，安装前列出能力清单（参考 claude plugin validate）
维护量要跟进 Claude Code 和 Codex 两套 CLI 协议的变化优先对接 ACP 这类已有适配层，而不是各自的私有流格式

一条今天就能试的捷径

Claude Desktop 的 Code 标签页自带浏览器面板，能在对话旁打开 localhost 页面；mods 又能启动进程、发 HTTP 请求、用 $.prompt.submit 往会话里发消息。理论上，“skill 启动本地 UI 服务 + 浏览器面板显示 + 一个 mod 做桥”就能在官方 app 里实现“左 chat 右工作台”，不用自己重写聊天窗。这条路没有实测，建议作为第一个验证实验。注意它只在 Claude Desktop 里成立，属于绑定单一生态的方案，只适合作为验证，不适合作为最终形态。

建议路线：不发明新协议，做“在本地 agent 旁边跑 MCP Apps 的宿主”

建议定位：一个开源桌面宿主，左边是用户自己的 Claude Code 或 Codex 会话，右边渲染 skill 自带的 MCP Apps 格式 UI，两边通过工作区文件和消息双向联动。项目名 skillframe 可以用，它不含 Claude 字样。

技术选型

层建议理由
UI 格式MCP Apps（ui:// 资源 + 沙箱 iframe）开放标准，Anthropic、OpenAI 都支持；SDK 自带给宿主用的 app-bridge 模块和 basic-host 示例；官方宿主补齐时 skill 不用重写
接 agent直接启动官方 CLI：claude -p stream-json（你已实现）、Codex app-server；评估 ACP 适配器合规姿势最稳；ACP 能一次接入多个 agent，但 Claude 适配器基于 Agent SDK，订阅政策上比直接调 CLI 更灰
skill 声明在 skill 文件夹里加一个 ui/ 目录和清单，不改 SKILL.md 标准不装宿主时 skill 照常工作，降级优雅
桌面壳Tauri 或 Electron（你现在是 Python 窗口）跨平台分发、自动更新更成熟
分发GitHub + npx 初始化器；可选上架 Claude Code 插件 marketplace与 career-ops 同款，安装门槛最低

分阶段计划

  1. 验证（1 周）：做两个小实验。一是上一节的“浏览器面板 + mod 桥”；二是把 Resume Studio 的预览页做成 MCP App，在 Claude Desktop 聊天里用本地 stdio server 跑起来。两个都顺，说明官方已经够用，你应该做“在现有 agent app 里加 UI 的工具包”而不是新 app。
  2. 抽取宿主（2–4 周）：从 Resume Studio 拆出通用部分：聊天面板（权限卡片、提问卡片、中断、附件）、文件监听刷新、“当前屏幕上是什么”的上下文注入（你用 --append-system-prompt-file 做的那套）。
  3. 旗舰 skill（2–4 周）：Resume Studio 迁到新宿主；再给一个热门纯文档 skill（如 career-ops 的追踪表）做 UI，证明“给别人的 skill 加 UI”很容易。
  4. 发布：一段 60 秒演示视频（同一个 skill，纯文字 vs 带 UI），发 Hacker News、X、Reddit、V2EX，并提 PR 到 awesome-skills 一类列表。

怎么判断值不值得继续

  • 发布后 4 周内，有没有别人写的带 UI skill？这是“基础设施”是否成立的唯一硬指标，star 数只是关注度。
  • 如果只有你自己的 skill 在用，就把精力收回到 Resume Studio 本身。它仍是一个好作品，也是求职时的代表项目。
  • 一旦 Anthropic 宣布 mods 支持 HTML 或 Code 标签页渲染 MCP Apps，就把重心切到“跨 agent + 开发工具链”，不要硬拼宿主。
